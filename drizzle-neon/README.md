# Fresh Neon migration chain

Only this directory is active for the Neuton-owned identity database. The explicit runner requires `0000_neuton_baseline.sql`, its own baseline marker and unchanged SHA-256 history. The chain includes the complete baseline, tenant integrity, restricted policies/routines, business triggers and shop bootstrap. Historical SQL in `drizzle` is not executed by the new runner.

The runner uses MIGRATION_DATABASE_URL only and never loads environment files. Supply it through the shell/deployment environment. Provision restricted roles before the baseline. Initialization refuses existing application relations or a legacy ledger. One transaction-level advisory lock serializes migration batches; DDL, marker and ledger changes commit together. A failed batch rolls back. There is no reset, owner fallback, schema push or manual marking path.

Handwritten migrations are registered as Drizzle custom migrations. The latest snapshot includes the declared RLS flags; FORCE RLS, helper grants, policies, trigger bodies and column-specific composite-FK SET NULL clauses remain explicit SQL. The installed Drizzle version cannot express a SET NULL column list, so review any regenerated composite FK to preserve the required shop_id. Application consumers adopt the scoped transaction/routine interfaces in the subsequent implementation phases; this chain alone does not complete the authentication migration.
